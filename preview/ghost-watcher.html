// three ways to check every commit

Before the push. After the push. From your CI.

Pick one or use all three. Each runs on your hardware, against your model.

01 · BEFORE THE PUSH

Stop the risky change at the developer’s desk

On a developer’s machine, choose Ghost Triple Crown™ Pre-Push Analysis, then Enable for a Repository. From then on, every git push runs the Ghost Triple Crown™ on the changed files first, and asks before a high-risk change leaves the machine.

02 · AFTER THE PUSH

Cover every repository without asking a developer to install anything

Ghost Watcher™ Local scans on the hub every time someone pushes to a repository on your own git server. It works with GitHub Enterprise Server, GitLab (self-managed), Bitbucket Server, Gitea and Forgejo. Each push is checked against your git server’s signature before anything in it is trusted, and on GitHub Enterprise Server the hub can post each commit’s risk score back as a comment on the commit.

03 · FROM YOUR CI

Wire it into the pipeline you already run

A CI runner inside your network (Jenkins, GitLab Runner, a self-hosted GitHub Actions runner, anything that can run a command) starts scans with ghost --no-interactive, or through the hub’s REST API with a scan-control key. The build gets a pass or fail and a findings file to act on.

Why not a cloud-hosted runner? A runner hosted by GitHub, GitLab or another cloud service runs outside your network and cannot reach the model on your own hardware, so Ghost Architect™ Local does not use one. That is the point: the code and the model stay on your machines.

// setup

Ghost Watcher™ Local in four steps.

On the hub, in the Admin Console. Your git server sends a webhook; the hub does the rest.

  • 1

    Enable the Watcher

    On the hub, open Admin Console, Ghost Watcher™ Local and choose Enable Watcher. The screen shows the webhook URL.

  • 2

    Make a webhook secret

    Choose Regenerate Webhook Secret and copy the secret it shows. It is shown once.

  • 3

    Add the repository

    Under Manage Watched Repositories, give the repository’s name as your git server writes it and the folder on the hub where a checkout of it lives.

  • 4

    Point your git server at the hub

    On your git server, add a webhook for push events to that URL, with that secret. Each push is then scanned on the hub’s own queue, and its report lands with every other.
