How we ship: three votes before any change goes out

One founder, two AI reviewers, and a rule that nothing ships until all three agree. On one weekend it put out three npm releases, and the same checks we sell looked at every one of the 47 commits.

A note on the name, October 2026: we used to call this the Ghost Triple Crown™ Process. The name now belongs to the product’s three-pass commit check (Blast Radius™, Conflict Detection™ and Ghost Brief™), so here it is simply the three-vote process.

The problem with solo AI development

Most developers using AI tools are doing one of two things. Vibe coding: paste a problem in, take whatever comes back, ship it when it looks fine. Or AI-assisted coding: Copilot or Cursor suggesting completions while they type.

Both share the same flaw. One pass, one perspective, and no check on whether the AI did what was intended, opened a security hole, or broke something three files away.

The three-vote process was built to solve that. Not with more AI. With structure.

The four roles

  • 1

    Reviewer

    Analyzes the problem, designs the solution, writes the precise prompt. Reads every output before it moves forward. Accepts or declines results. Never touches the code directly.

  • 2

    Executor

    Takes the Reviewer’s analysis, refines it into an actionable approach, and reports results back. The communication layer between design and implementation.

  • 3

    Claude Code

    Gets the Reviewer’s final approved prompt. Reads files, applies changes, runs tests, pushes commits. Reports results back to the Executor.

  • 4

    Founder

    The human gate at every transition. Approves before the Executor refines, approves the refined prompt, approves the final prompt before Claude Code runs, and approves the push. Nothing ships without the founder’s approval at all four gates.

The flow

The process runs the same way on every change, every time.

  • 1

    Reviewer drafts

    Analyzes the problem, proposes a solution, writes the approach.

  • 2

    Founder approves

    Reads the Reviewer’s analysis. Questions it if something feels wrong. Approves or sends it back.

  • 3

    Executor refines

    Takes the approved analysis and sharpens it into a precise implementation prompt.

  • 4

    Founder approves again

    Reads the refined prompt before anything is executed.

  • 5

    Reviewer writes the Claude Code prompt

    Final architectural review. Writes the exact prompt Claude Code will execute.

  • 6

    Founder approves the prompt

    One more gate before code runs.

  • 7

    Claude Code implements

    Reads files, applies changes, runs tests, reports results.

  • 8

    Executor reports

    Surfaces what Claude Code did and flags anything unexpected.

  • 9

    Founder reviews results

    Reads the output before passing it to the Reviewer.

  • 10

    Reviewer accepts or declines

    If accepted, the Founder approves the push. If declined, back to step 1.

The weekend that proved it

Over the weekend of June 27 and 28, 2026, this process shipped three npm releases of Ghost Architect™ in two days.

47 commits. 14 test suites. Three npm releases. HTML escaping across six security surfaces. LLM-authored remediation prompts for every finding. A date range filter in Ghost Portal. One founder, two AI reviewers.

Every change went through the full flow. Reviewer drafted. Founder approved. Executor refined. Founder approved. Reviewer wrote the Claude Code prompt. Founder approved. Claude Code ran. Executor reported. Founder reviewed. Reviewer accepted. Founder approved the push.

Nothing shipped that did not pass all three votes. Not one commit.

Why three votes

The Reviewer catches what the Executor misses. The Executor catches what the Reviewer over-engineers. The Founder catches what both AIs agree on but is strategically wrong.

No single AI has the full picture. The Reviewer does not execute, so it never sees the edge cases that appear only when code runs. The Executor does not architect, so it follows instructions without asking whether they are right. Claude Code does not decide, so it implements whatever it is told.

The Founder holds the context neither AI has: the business constraints, the cash flow, the customer conversation from this morning, the direction for next quarter. That context shapes every decision.

Three votes before anything ships. Reviewer. Executor. Founder. If any one of the three disagrees, nothing moves.
