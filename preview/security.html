// ghost architect™ local

Zero egress, at the code level, with the inventory that proves it

The model runs on your hardware. Your source never leaves your network while Ghost Architect™ Local works, because there is nothing on the other side to send it to. Each point below is something your reviewer can check, not something they have to take on trust.

  • One call home, once. License activation sends the license key and an install id to ghostarchitect.dev and receives a signed license. Nothing from the codebase is in the request. The license is verified on the machine with Ed25519; there is no phone-home to keep running. Fully air-gapped installs take the signed license file instead, with ghost --install-license.
  • Answer “where can our data go?” with a printout, not a policy. The product prints every destination it is capable of sending to (email, webhooks, team sync, PR comments, a git server), what each one would carry, and the switch that turns it off. The inventory is generated from the code that gates the traffic, so it cannot drift from what the product does.
  • Zero-egress mode refuses; it does not warn. It comes with every license. Turn it on and every outbound integration is refused at the code level, including a spoke enrolling against a hub outside your LAN. The refusal is written to the audit log.
  • A model switch you control. Air-gapped, local, or a cloud API on your own key. The Cloud API position is off by default, and each project is set to Local only or Cloud allowed, so a client whose contract forbids the cloud never touches it.
  • Client reports wait for approval. A report meant for a client goes out only after an administrator approves, schedules or rejects it from an email link, and every sent report is archived.
  • Evidence for the audit, already collected. Every scan ending, completed, failed, canceled, killed or lost, is a row in the compliance ledger with the scan it belongs to, the person, the project label and the directory name (never the full path). Exports are CSV or PDF, signed, with the signing key rotated from Admin Console.
  • A hash-chained audit log. The audit log is chained line by line, and the Audit page verifies the chain inside every file it opens and says which files it opened, so “the chain verifies” and “no file is missing” are two claims kept apart on purpose.
  • Reports that name their coverage. A report says how many files it read of how many exist and claims nothing about the rest. A scan that never finished counting says nobody counted, never zero.
  • Secrets stay out of the model. Credentials, keys, connection strings and tokens are redacted from the text the model receives, and the redactor fails closed: a file it cannot redact is not sent.
  • Verify it yourself. Run it behind a packet inspector with zero egress on. After activation you will see LAN traffic between your own machines and nothing else. The product ships as source in the tarball you install, so the code that makes these claims is the code you can read.

// ghost open™ data flow

Where your code goes during a Ghost Open™ scan

Ghost Open™ is the single-user CLI that uses Anthropic’s API on your own key. Here is the complete path the data takes. There are no hidden steps.

  • Step 1

    Ghost Open™ reads your local files. Nothing is uploaded yet. File reading happens entirely on your machine.

  • Step 2

    Relevant code chunks are sent directly to Anthropic’s API using your own API key. The traffic goes from your machine to Anthropic. We are not a relay, proxy or middle hop. What Anthropic keeps, and for how long, is set by Anthropic’s own policy and your agreement with them; see Anthropic’s privacy policy.

  • Step 3

    Anthropic’s API returns analysis. The response comes back to your machine.

  • Step 4

    Ghost Open™ writes the findings report locally as PDF, Markdown or text, on your machine only. Nothing is published anywhere.

  • Step 5

    A small heartbeat ping containing the CLI version, an anonymized install ID and the event type (for example cli-firstrun-docker) may be sent to our telemetry endpoint. This ping contains no source code, no file paths, no findings, no API keys and no personally identifiable information. Set GHOST_NO_PING=1 to switch it off.

// architecture

What we operate, and what we do not

  • We operate

    A static marketing website (this one); the license service that answers activation calls (a license key and an install id, nothing from your code); the workers behind this site’s forms; a Cloudflare Worker and an Airtable base that receive and store anonymous Ghost Open™ heartbeat pings; and the Ghost Open™ package on the public npm registry.

  • We do not operate

    Any server that receives customer source code from either product. Any database of customer findings reports. Any AI inference infrastructure that your installed product sends code to. Any analytics service that profiles your team or users.

  • Keys

    Your Anthropic API key for Ghost Open™ is stored locally on your machine in a configuration file you control. It is never transmitted to us. You can rotate or revoke it at any time without involving us.

  • Done for you

    Our done-for-you services are different: there, a copy of your code comes to us for the job. Each one says exactly where the code goes on its own page. Ghost Inheritance Audit™.

// compliance posture

No SOC 2 badge, because neither product puts anything of yours on our side to certify.

Ghost Architect™ is operated by its founder with a deliberately minimal infrastructure footprint. We do not currently hold SOC 2 Type II or ISO 27001 certifications, and we would rather say so than display badges we have not earned.

We are comfortable working with security-conscious teams without those certifications because the products are built so that the data those frameworks protect never enters our infrastructure. Your source code, your API keys and your findings reports stay on systems you control. There is no Ghost Architect™ data plane for an auditor to certify.

When enterprise revenue justifies the audit cost, and an enterprise customer requires it as a condition of contract, we will pursue SOC 2 readiness through a recognized provider. Until then, we point your security team to this page, to the egress inventory and ledger inside Ghost Architect™ Local, and to the source code itself.

// for security reviewers

Verify these claims yourself

Everything on this page can be checked independently.

  • Watch Ghost Architect™ Local’s network. Turn zero egress on and run it behind a packet inspector. After activation you will see LAN traffic between your own machines and nothing else.
  • Read the inventory. Admin Console, System Settings, Egress Inventory lists every vector, its current on or off status, exactly what it would send, and how to turn it off.
  • Inspect Ghost Open™. It installs from npm as ghost-architect-open, source-available under the Business Source License 1.1. Read the package contents before you run it.
  • Watch Ghost Open™’s network. You will see two endpoints: the Anthropic API and our telemetry endpoint. Set GHOST_NO_PING=1 and only the Anthropic calls remain, on your key.
  • Need air-gapped analysis? That is Ghost Architect™ Local. Ghost Open™ needs a connection to Anthropic’s API to scan; it needs no connection to us.
