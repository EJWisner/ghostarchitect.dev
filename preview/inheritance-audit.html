// four analyzers · one report

What you get.

Four analyzers run against the codebase and come together in one executive-summary report you can hand to a deal committee, a board or a client without an apology.

01 · STACK REALITY

What is really there.

An independent inventory of every framework, runtime and dependency in the code, read from the repository itself, not from the seller’s deck.

  • Framework and runtime detection across any language
  • End-of-life flags with publication dates
  • Version drift across services
  • Checked against the repository’s contents, not its docs
02 · KEY-PERSON RISK

Who walks out the door with the know-how?

Find out which people the codebase depends on, and which of them have already left, before you price the deal.

  • Anonymized authorship concentration
  • Departed-contributor flags
  • Concentration per subsystem
03 · HIDDEN DEPENDENCIES

What you owe.

Find the copyleft license and the dead dependency before they become a price adjustment after close.

  • License classification across the dependency tree
  • Copyleft exposure in commercial code
  • End-of-life dependency flags
  • Transitive dependency risk
04 · MODERNIZATION ROADMAP

What to do.

A confidence-rated 90-day plan with a stabilize-or-rebuild recommendation, prioritized by deal impact.

  • Stabilize-or-rebuild recommendation
  • Confidence rating (LOW / MEDIUM / HIGH)
  • 90-day plan with deal-tier priorities
  • Every finding traces to the source it came from

What it does not do, on page one where it belongs. It does not match code against an open source database, so it will not find copied code with the license stripped; when the R&W policy calls for an open source audit, commission one. It is not a CVE scanner, does not analyze binaries and does not test runtime behavior. It does not replace a full security audit or operational due diligence. It tells you where to look, fast.
