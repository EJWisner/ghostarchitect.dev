Ghost Architect™ Local 8.1.20 November 11, 2026 2 min read By Ernst J. Wisner

A password a person chose is redacted in most of the places that missed it

8.1.20 replaces a password such as Summer2024! in 84 more of the forms a password is written in, before your model sees the file and in everything Ghost Architect™ writes.

A password a person chose is not random and has no service's shape, so it can be replaced only where the form of its line is known. We ran nine such passwords through each of 156 forms. Before this release your model was shown every one of them in 92 of the forms. Now it is shown none of them in 148: in code (Go's short assignment, typed declarations, names that end in pass, the name given as an argument), in commands (--password under any command, sshpass, docker login, redis-cli and more), in SQL (IDENTIFIED BY, CREATE and ALTER USER), in settings (make and batch files, PGPASSWORD, requirepass, .pgpass) and in documents. A password that holds an apostrophe, shown before in 74 of the 77 forms that write it between double quotes, is now replaced whole in all 77.

This is not every form. Still shown to your model, among the commonest: a default handed to a lookup (os.getenv("DB_PASSWORD", "...")), a method that sets it (setPassword("...")), a comparison, the names pass and pw alone, and a password with no name beside it. A value a shell or a template fills in, help text, labels and prompts are left as written on purpose. A password of fewer than eight characters is replaced where it is written but not remembered for the scan.

The redaction self-check, ghost --redaction-check, now plants 125 such passwords in twenty-five forms. Its dated report lists the forms and says what a passed run does not show.

This release also moves node-forge, a library used only when the portal gets its certificate from Let's Encrypt, to 1.4.3, past four advisories published after 8.1.19 shipped.
