Ghost Architect™ Local 7.4.6 September 23, 2026 2 min read By Ernst J. Wisner

An update no longer throws away the work the model is doing

Before an update, Ghost stops the scans on the machine and starts them again afterwards. It now waits for the scan the model is actually working on, whether that is a pass or a merge step, uluation now.

On the Scan Queue, Recently ended shows these scans as "stood down" instead of "killed", because they carry on by themselves after the update.

The same code is now split into the same passes every time. Files that ranked equally were kept in the order the disk listed them, which changes from run to run, so most saved pass answers went unused on a repeat scan. Equal files are now ordered by their path, and a repeat scan keeps its saved pass size when only the machine's speed setting has changed. The first scan of each project after this update splits its files once more under the new order.

When a scan is stopped, the email counts only the saved passes a restart will reuse. And when LLM Status says a model call read less of its prompt than it was sent, it names the scan, the step and the time of that call, and when it stops counting.
