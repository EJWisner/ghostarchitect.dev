Ghost Architect™ Local 8.0.49 October 14, 2026 4 min read By Ernst J. Wisner

One client stays local. Another may use the cloud. Same hub.

Since 8.0.49, every project in Ghost Architect™ Local has a data boundary: Local only or Cloud allowed. One client's code can stay on your own network while another client's project uses a cloud model, on the same hub, and every report says which it was.

An agency rarely has one kind of client. One client's contract says its code never leaves your building. Another is happy for a frontier model to read its open-source fork, because the answers are better and the code is public anyway. Until now the choice was made for the whole hub: either everything stayed local, or anything could go out.

8.0.49 makes it a choice per project, and makes the choice hard to get wrong.

Local only means local, on every hop

A Local only project's model calls never go to a cloud model, to a model at a public address, or through a proxy. That holds on every hop a call can take: this hub's own model, an inference node, a peer hub, and a spoke's call to its hub. A VPN such as Tailscale or ZeroTier counts as inside your network, and so do private LAN addresses and Mac .local names. A model server reached through its public internet address does not. Chapter 4 of the manual lists the exact ranges.

Set on purpose, never by accident

  • New projects start Local only. A scan with no project name is Local only too.
  • An administrator changes it, in the portal, the REST API or with ghost --data-boundary, with their own password. Every change, and every refused attempt, goes in the audit log.
  • A project is named by its exact label, so two similar names never share a setting.
  • Zero-egress is still the master switch. While it is on, no project can be Cloud allowed.

Every report says which

Each report and Ghost Brief™ carries a line such as "Data boundary: local only. No model call for this project went to a cloud model." The scan log notes each call that was kept local. When a client asks where their code went, the answer is on the report you already sent them.

Nothing changes the day you upgrade

A hub that already sent model calls to a cloud or hosted model keeps its existing projects Cloud allowed. A hub that was local keeps them Local only. The boundary starts doing its work from the next project you set, not by surprising the projects you have.
