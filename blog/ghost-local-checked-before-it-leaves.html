Ghost Architect™ Local 8.1.34 November 16, 2026 3 min read By Ernst J. Wisner

Every model call is checked again just before it leaves

Ghost Architect™ Local has redacted your files as it loads them since the first build. But a model does not only read file contents. It reads which file each block came from. A file named token- followed by a real GitHub token sent that token straight to the model.

The last door, guarded

Since 8.1.33, every call to a model is read for secrets one more time, just before it leaves, on every path a call can take: your local model, a peer hub, the cloud. Each file is read under its own name, so nothing else in the call changes. If a call cannot be read in full, it is not sent. A scan that stops is better than a secret that leaves.

We tested it by planting each of the 16 token shapes Ghost recognizes in file and folder names, in every scan mode, then searching everything that was sent. The release before sent every one of them.

The path nobody uses yet, closed anyway

Ghost Architect™ Local still carries a way to send a batch of requests to Anthropic. Nothing reaches it today, and zero-egress mode refuses it. We gave it the same last check in 8.1.34 anyway, and made it refuse anything it cannot read, because "unreachable" is one setting away from reachable.

What this means for you

When a scan runs on a cloud model with your permission, what leaves your machine is what Ghost read, checked twice, with every secret it recognizes replaced. When it runs on your own model, the same holds, so a log or a peer hub never holds what your code tried to hide. If you think a file name holding a secret reached a model that is not on a machine you control, replace the secret.
