Check redaction on your own hub

"Trust us" is not an answer a security team should accept. Since 8.1.18, ghost --redaction-check runs the redaction test we run before each release, on your hub, with your settings, and writes you a dated report.

What it does

It makes a few hundred fake credentials on the spot, puts them in a small made-up codebase in a private folder, scans it in every scan mode, and searches everything Ghost Architect™ wrote, printed, sent and answered for any of them: reports, PDFs, logs, the screen, portal pages, REST API answers, email, webhooks and SIEM lines.

None of your files is scanned, your model is not asked, and nothing leaves the hub. It takes about a minute.

A sweep of what was already written

The same command reads the files Ghost Architect™ already wrote (reports, logs, saved answers, queued email, exports) and names each place where today's redaction would replace something: the file, the line or field, and the kind of credential, never the value. A report written by an older version is found this way. No file is changed.

A dated report to file

Markdown and PDF, in redaction-self-checks under the Reports folder: what was planted, what was done, what was found, and what the run does not show. System Status shows the last result, and each run goes in the audit log.

Five gaps it found first

Building the self-check found five ways a credential could get past redaction, and 8.1.18 closed them: a credential a model wrote into a finding's title, a scan that remembered only its first 200 credentials, a database password after its -p flag, a credential cut short before it was redacted, and the second of two Azure storage connection strings on neighboring lines. That is the point of a test that can fail.

What it is not

A passed self-check shows what your hub did with the credentials one run planted. It is a self-check, not a certification, and the report says so.
