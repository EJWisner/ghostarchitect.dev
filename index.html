// common questions

Common questions.

What exactly does Ghost Architect™ do?

Ghost Architect™ scans your codebase and produces a structured triage report, categorizing every finding by severity (Critical, High, Medium, Low), flagging architectural risks, security vulnerabilities, and conflict mismatches. It gives your team a prioritized map of where to start, not a raw dump of everything that could conceivably be wrong.

Does Ghost Architect™ upload my code anywhere?

No. Ghost Architect™ runs on your own infrastructure. Your API key, your GitHub Actions runner, your GitHub repo. Ghost has no servers. Analysis calls go directly from your machine to the model provider you chose using your own API key. With Ghost Architect™ Local, the model runs inside your network as well, and nothing leaves the building.

What is Ghost Brief™?

Ghost Brief™ is the governed AI remediation pipeline built into Ghost Architect™. After any scan, Ghost converts your findings into a validated, blast-radius-aware prompt pack. Each prompt tells your AI coding agent exactly what to fix, which files to touch, and which files to leave alone. Ghost never writes or modifies code. Ghost scans, Ghost briefs, the AI fixes.

What languages and platforms does it support?

Any codebase, any language, any platform. PHP, JavaScript, TypeScript, Python, Ruby, Java, it doesn't matter. Ghost is framework-aware and analyzes code structure, dependency relationships, configuration files, and integration patterns regardless of what stack you're running.

How is this different from a linter or static analysis?

Linters catch syntax errors and style violations. Static analysis tools find known vulnerability patterns. Ghost Architect™ reasons about your codebase architecturally: how components relate to each other, where integrations are fragile, what the blast radius of a change is, and what a senior architect would flag on day one.

Can I use it on a client's private repository?

Yes. Ghost Architect™ supports private GitHub, GitLab, and Bitbucket repositories. You authenticate with a personal access token, Ghost clones the repo locally, runs the scan, and removes the local clone when done. Your client's code never touches any third-party infrastructure beyond your own.
